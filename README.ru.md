# Tessera

[English](README.md) · [简体中文](README.zh-CN.md) · [Français](README.fr.md) · [Español](README.es.md) · **Русский** · [العربية](README.ar.md)

[![Licence: AGPL-3.0](https://img.shields.io/badge/licence-AGPL--3.0-blue.svg)](LICENSE) [![Commercial licence available](https://img.shields.io/badge/commercial%20licence-available-brightgreen.svg)](LICENSE-COMMERCIAL.md) [![Platform: Windows](https://img.shields.io/badge/platform-Windows%2010%2F11%20x64-lightgrey.svg)]()

**Tessera** — многофакторное зашифрованное хранилище для Windows, в котором
также есть менеджер паролей, история буфера обмена, заметки, ИИ-ассистент и быстрый
файловый менеджер. Всё живёт за одной разблокировкой; ничего не покидает ваш компьютер,
если вы явно это не настроите.

> Статус: `0.1.8`, активно развивается. Только Windows 10/11 x64 — несколько функций
> (Windows Hello, интеграция с проводником, глобальные горячие клавиши для файлов)
> напрямую привязаны к API Windows.

## Что внутри

| Функция | Что делает |
|---|---|
| **Шифрование файлов** | Шифруйте/расшифровывайте любой файл в единый файл `.ivault`. Три профиля: **постквантовый** (по умолчанию — AES-256-GCM для содержимого, а ключ каждого файла дополнительно упакован с помощью ML-KEM-1024, так что взломать нужно обе конструкции), классический AES-256-GCM или ChaCha20-Poly1305. Профиль одинаково действует и для нескольких выбранных файлов, и для папки целиком. Пакетный выбор сразу многих файлов. Имена файлов и контрольные суммы хранятся в *зашифрованном* заголовке, поэтому украденный `.ivault` не раскрывает ни то, ни другое. У расшифровки есть отдельный пункт для папок рядом с пунктом для файлов, а открытие зашифрованной папки показывает её содержимое без предварительной расшифровки контейнера: список читает лишь те несколько сотен килобайт, где лежит оглавление архива, поэтому папка на 10 ГБ открывается так же быстро, как маленькая, а распаковка пишет каждый файл ровно один раз. |
| **Безопасное удаление + поиск остатков** | По желанию перезаписывает, а затем удаляет оригинал после шифрования, и ищет оставшиеся незашифрованные копии — резервные копии Office/WPS и одноимённые копии в других местах на диске. |
| **Менеджер паролей** | Полный CRUD, по умолчанию скрыт, импорт из CSV паролей Chrome/Edge/Firefox (открытый CSV безопасно удаляется после импорта), экспорт обратно в формат Chrome/Edge. |
| **История буфера обмена** | Зашифрованная история с автоклассификацией (URL / email / телефон / **формула** / код / текст), закрепление, поиск, виртуальная прокрутка, чёрный список по приложениям, корзина, значок в трее и глобальная панель по `Ctrl+Shift+V`. Нажмите на миниатюру, чтобы открыть изображение целиком (во весь экран или в плавающем окне — на выбор) с масштабированием, перемещением и копированием по щелчку. Экспорт всего / только закреплённого / только скрытого / только отмеченного, с множественным выбором и выбором всего; импорт нескольких файлов сразу, после чего оригиналы безопасно удаляются. Импорт никогда не оставляет вторую копию того, что уже есть: совпадающая запись объединяется, а не дублируется, и её метки закрепления и скрытия сохраняются. Для дубликатов, уже находящихся в хранилище, есть очистка: она показывает найденное и объединяет только после подтверждения, а отложенное отправляется в корзину. |
| **Заметки** | Markdown-заметки с изображениями, категориями и полнотекстовым поиском, хранятся в зашифрованной базе данных. Категории сортируются по имени, по числу заметок, по последнему обращению — или в том порядке, который вы расставите сами. Над списком четыре счётчика — Всего, Активно, Скрыто, Удалено — и каждый открывает именно то, что считает: нажмите «Скрыто», чтобы увидеть эти заметки, «Удалено» — чтобы открыть корзину, нажмите ещё раз, чтобы вернуться. Те два, что выводят скрытые заметки на экран, сначала просят подтвердить личность — тем же способом разблокировки, что и везде; скрытая заметка, отправленная в корзину, тоже остаётся за этой проверкой, а корзина сообщает, сколько записей она придерживает, чтобы короткий список никогда не выглядел как потерянные данные. Каждая заметка помнит, где вы остановились при чтении или правке, и возвращает вас туда при повторном открытии — в том числе в заметках, достаточно больших для постраничной загрузки. Большая заметка появляется за миллисекунды и остаётся отзывчивой при вводе: текст отрисовывается блок за блоком в фоновом потоке, поэтому первый экран не ждёт остального — заметка на 4 МБ показывает начало примерно за 40 мс, а не за полторы секунды. |
| **ИИ-ассистент** | Общайтесь с любым OpenAI-совместимым эндпоинтом (по умолчанию DeepSeek). Список моделей запрашивается у провайдера в реальном времени и показывается с датой выпуска каждой, от новых к старым; модели, о которых приложение ничего не знает, всё равно отображаются и доступны для выбора, а снятые с поддержки помечаются, а не отказывают молча. Выбранная модель применяется ко всем ИИ-функциям приложения. Импортируемые «навыки» в том же формате `SKILL.md`, что и Claude Code. История переписки хранится в зашифрованном виде. |
| **Файловый менеджер** | Высокоскоростное копирование / вырезание / вставка / удаление, совместимое с собственным буфером обмена Проводника, с карточкой прогресса в реальном времени. Глобальные хуки `Ctrl+V` / `Delete` / `Shift+Delete`. |
| **Тест скорости сети** | Запускайте и визуализируйте тесты соединения с сохранением истории. Пропускная способность считается так же, как её считают публичные спидтесты: соединение опрашивается отрезками по четверти секунды, а итоговой цифрой берётся 90-й перцентиль установившегося режима, поэтому разгон TCP и отдельные провалы не утягивают результат ниже того, что линия действительно даёт. Задержка - это один оборот TCP, а не полный HTTPS-запрос, так что время обработки на сервере в неё не попадает; джиттер - среднее изменение между соседними замерами, то есть именно та величина, от которой зависит, выдержит ли звонок или игра. К каждому результату прилагается показатель стабильности: он говорит, насколько разошлись быстрые и медленные моменты теста, и тем самым отвечает, значит ли что-нибудь другое число при следующем запуске. |
| **Подписанное автообновление** | В релизе **два файла: установщик и портативный exe**, по одному на каждую форму. Доверие обеспечивает встроенная в него подпись Authenticode: она сверяется с именем издателя и отпечатком открытого ключа, зашитыми в сборку, — поэтому достаточно бесплатного самоподписанного сертификата, а платный сертификат УЦ лишь убирает предупреждение SmartScreen. Неподписанная, изменённая или подписанная другим ключом загрузка удаляется, а сборка без заданного подписанта отклоняет любое обновление — никогда «разрешить, если не настроено». Релиз с более чем одним exe отклоняется, а не угадывается. Установка транзакционна: после выхода приложения подпись проверяется повторно, старый exe сохраняется, а неудачная новая версия откатывается автоматически. Хранилище, учётные данные и настройки лежат вне exe, и обновление их не трогает. |
| **Синхронизация между устройствами** | Скопируйте на телефоне — вставьте на ПК, и наоборот. Текст, форматированный текст, код, математические формулы и физические символы сохраняют оформление; изображения тоже передаются. Отправляйте любой файл или папку на одно устройство или сразу на несколько, с возобновлением после обрыва и сквозным шифрованием. Четыре способа сопряжения — QR-код, код сопряжения, выбор устройства из списка находящихся рядом или ввод адреса вручную — около десяти секунд в любом случае. Когда список рядом оказывается пустым, активное сканирование сети находит устройства, до которых не доходит многоадресное обнаружение, а проверка связи называет шаг, который не проходит. Отправка из другого Android-приложения идёт через системное меню «Поделиться»: долгое нажатие на фото или файл, выбор Tessera, затем выбор сопряжённых устройств-получателей. Файлы уходят только на выбранные устройства — одно или несколько, каждый раз выбираются явно, — а буфер обмена всегда попадает на все сопряжённые устройства. После сопряжения устройство, снова появившееся в сети, переподключается само примерно за секунду, а сопряжение достаточно выполнить один раз: уже сопряжённые устройства находят друг друга в другой сети или после смены IP-адреса, без многоадресного обнаружения, которое многие роутеры отбрасывают. |
| **Очистка ПК** | Пять панелей, которые следят за самой машиной. Одна проверка разом просматривает мусорные файлы, кэш браузеров, следы работы, плагины, автозапуск, источники всплывающих окон и устаревшие ссылки в реестре — и заполняется по мере готовности каждой части, а не заставляет смотреть на застывший экран. Место на диске охватывает облегчение системного диска, большие файлы, место по папкам, дубликаты (сравниваются по размеру, затем по выборке из каждого файла, затем целиком) и оптимизацию, которая на SSD выполняет TRIM вместо дефрагментации. Автозапуск и меню перечисляет всё, что стартует при входе — реестр, папку автозагрузки, запланированные задачи и службы, — а также каждый пункт контекстного меню, вместе с блокировщиком всплывающих окон, работающим на двух уровнях. Установленные программы показывают всё, что есть на машине, а в инструментах собрано сорок две небольшие утилиты с поиском и закреплением. Перед очисткой пробный запуск проходит настоящий путь кода, не трогая ни байта, и сообщает, сколько освободится на каждом диске и что вернуть не выйдет. Панели открываются на прошлом результате, пока позади идёт новое сканирование. Можно добавить правила, указывающие на ваши папки — но не на корень диска, системную папку или данные самого хранилища, — и оставить плановый проход только смотреть. |
| **Понятно, что можно убрать** | У каждой записи одна из пяти оценок — нужно самой Windows, драйвер, то, чем вы пользуетесь, необязательное, реклама — с причиной, написанной словами. То, что нужно Windows, заблокировано и не выбирается; сервер отказывает, даже если его об этом попросить. Всё нераспознанное считается необязательным, но не мусором: пропустить файл кэша стоит мегабайтов, удалить драйвер — половины дня. |
| **Всё убранное можно вернуть** | Кэш и временные файлы удаляются насовсем — именно это освобождает место. Ваши собственные файлы уходят в Корзину. Записи реестра, автозапуска и обработчики контекстного меню *отключаются с резервной копией*, а не удаляются. Перед любым изменением экспортируется резервная копия реестра, и если экспорт не удался, не меняется ничего. |
| **Интерфейс и оформление** | Единый визуальный язык на всех экранах — один и тот же заголовок страницы, одни и те же карточки разделов и цвета состояний везде, ничто не выглядит приделанным сбоку. Восемь акцентных цветов, два визуальных стиля («Улучшенный нативный» / «Восточная техно-роскошь»), система/светлая/тёмная и режимы «Простой» или «Профессиональный», которые скрывают или раскрывают диагностическую глубину. Android-компаньон использует ту же палитру и ту же разбивку на разделы. |
| **6 языков** | English, 简体中文, Français, Español, Русский, العربية — переключается в любом месте, в том числе на экране входа. |

Пять способов разблокировки, **достаточно любого одного**: пароль · код из письма ·
приложение-аутентификатор (TOTP) · Windows Hello · одноразовый
ключ восстановления.

Windows Hello здесь — это тот способ, который вы зарегистрировали: **лицо, отпечаток или
PIN-код**. Окно системное, поэтому компьютер с камерой Hello и без сканера отпечатков
разблокируется по лицу.

Экран входа **открывается на Windows Hello и сразу же запрашивает его** — нажимать ничего не
нужно. На машине, где Hello никогда не привязывался к этому хранилищу, он молча переключается
на поле пароля, без сообщения об ошибке: попытка ничего не стоит.

## Начало работы

### Вариант A — скачать готовую сборку

На странице [Releases](../../releases) две сборки. Это одно и то же приложение —
берите ту, что удобнее вам.

| | `Tessera.Setup.exe` | `Tessera.exe` |
|---|---|---|
| | **Установщик** | **Портативная** |
| Куда ставится | выбираете вы | туда, куда положите файл |
| Ярлык в меню «Пуск» / на рабочем столе | есть | нет |
| Видна в «Приложения и возможности» | да | нет |
| Права администратора | не нужны (установка для пользователя) | не нужны |
| Запуск с USB-флешки | нет | да |
| Обновление умеет откатываться | нет | да |

Ни одна из сборок не пишет ничего за пределами вашего профиля пользователя.
**Удаление приложения не удаляет хранилище** — см.
[Где хранятся ваши данные](#где-хранятся-ваши-данные).

> При первом запуске Windows покажет «Система Windows защитила ваш компьютер». Это
> SmartScreen реагирует на самоподписанный сертификат, а не предупреждение о вирусе.
> Нажмите **Подробнее → Выполнить в любом случае**. Так будет только в первый раз;
> встроенные обновления этого никогда не вызывают.

Обе сборки обновляются сами, каждая оставаясь в своём виде.

### Вариант B — запуск из исходников

```bash
git clone <this repo>
cd Tessera

# Python-часть — все зависимости времени выполнения объявлены в pyproject
pip install -e .

# UI-часть (node_modules не хранится в репозитории)
cd modules/file_vault/ui && npm install && cd ../../..

# Запуск
python scripts/run.py run file_vault
```

Последняя команда запускает `npm run dev` внутри `ui/`, что стартует Vite и окно
Electron. Главный процесс Electron запускает `backend_server.py` как долгоживущий
дочерний процесс Python и общается с ним по NDJSON через stdin/stdout; закрытие окна
его останавливает.

Дополнительно — разблокировка по отпечатку требует привязок Windows Hello:

```bash
pip install winrt-Windows.Security.Credentials.UI winrt-Windows.Foundation
```

## Первый запуск: мастер настройки

При первом запуске мастер проведёт вас по шагам, по порядку:

1. **Установите пароль** — он оборачивает ваш мастер-ключ идентичности.
2. **Привяжите приложение-аутентификатор** — отсканируйте QR-код, подтвердите одним
   кодом.
3. **Привяжите разблокировку по отпечатку** — *автоматически пропускается*, если на
   этом ПК нет Windows Hello.
4. **Настройте email** — здесь необязательно, можно добавить позже в Настройках. См.
   ниже.
5. **Сгенерируйте ключ восстановления** — показывается один раз. Запишите его.

После этого каждый запуск открывает экран входа; пройдите любой один фактор — и вы
внутри.

## Настройка входа по коду из письма

Это способ разблокировки «пришли мне 6-значный код на почту». Он работает, отправляя
письмо **с вашего собственного почтового ящика через ваш собственный аккаунт SMTP** —
никакого сервера Tessera посередине нет, поэтому вам и нужно указать учётные данные
SMTP.

### Шаг 1 — получите пароль приложения у вашего почтового провайдера

Почти наверняка вы не сможете использовать свой обычный пароль для входа. Провайдеры
требуют отдельный пароль приложения (Gmail) или код авторизации (QQ, 163) для
сторонних клиентов:

| Провайдер | Где получить учётные данные |
|---|---|
| **Gmail** | Включите двухэтапную аутентификацию, затем Аккаунт Google → Безопасность → Пароли приложений. Вы получите 16-значный код; пробелы, которые показывает Google, нужны только для читаемости и **не являются** частью пароля. Google отключил «доступ для менее безопасных приложений» в 2022 году, так что пароль приложения (или OAuth) — единственный способ. |
| **QQ Mail** | Настройки → Аккаунт → включите сервис POP3/IMAP/SMTP, затем сгенерируйте 授权码 (код авторизации). Используйте его, а не пароль от QQ. |
| **163 Mail** | Настройки → POP3/SMTP/IMAP → включите сервис и задайте 授权码. Та же идея. |
| **Outlook.com / Microsoft 365** | **Не поддерживается.** Microsoft отключила базовую аутентификацию для SMTP AUTH в 2026 году; теперь эти аккаунты требуют OAuth 2.0 (XOAUTH2), который это приложение не реализует. Используйте другой почтовый ящик для кода или полагайтесь на остальные четыре способа разблокировки. |

### Шаг 2 — заполните настройки

На шаге мастера *Настройка email и исходящей почты*, или позже через
**Настройки → Обновить email и исходящую почту**:

| Поле | Значение | Типичное значение |
|---|---|---|
| Email для восстановления | Куда отправляется код (может быть тот же ящик) | `you@example.com` |
| SMTP-сервер | Исходящий хост вашего провайдера | `smtp.gmail.com` · `smtp.qq.com` · `smtp.163.com` |
| SMTP-порт | `465` для SSL, `587` для STARTTLS | `465` или `587` |
| Аккаунт отправителя | Полный адрес, с которого отправляется письмо | `you@gmail.com` |
| Пароль приложения | Учётные данные из шага 1 — *не* ваш обычный пароль входа | 16-значный пароль приложения / 授权码 |
| Использовать SSL | Отметьте для порта **465**; оставьте пустым для **587** (STARTTLS) | — |

> В Настройках пустое поле пароля сохраняет уже введённый ранее.

### Шаг 3 — отправьте тестовое письмо

Нажмите **Отправить тестовое письмо** и убедитесь, что оно действительно доходит. Если
нет — ошибка показывается дословно; обычные причины: неверная комбинация порта/SSL,
использование пароля входа вместо пароля приложения, либо SMTP ещё не включён на
аккаунте.

### Как это работает при входе

Выберите вкладку **Email** на экране входа и запросите код. Код состоит из 6 цифр,
действителен **10 минут**, используется **один раз** и хранится только в памяти
backend-процесса — на диск он никогда не записывается.

## Настройка приложения-аутентификатора

Отсканируйте QR-код мастера с помощью Google Authenticator, Microsoft Authenticator,
Authy или любого стандартного TOTP-приложения, затем введите текущий 6-значный код для
подтверждения привязки. Seed также можно ввести вручную, если сканирование
недоступно. Seed хранится в Диспетчере учётных данных Windows, а не в репозитории.

## Настройка биометрической разблокировки

Это обращается к настоящему сенсору Windows Hello. Требует двух пакетов `winrt-*` выше плюс
ПК с настроенным Windows Hello. Если Hello недоступен, мастер пропускает этот шаг, а
остальные четыре способа не затрагиваются.

Tessera спрашивает у Windows, какие биометрические сенсоры на этой машине действительно есть,
и берёт первый доступный в порядке **лицо → отпечаток → радужка**. Вкладка подписывается и
оформляется соответственно: машина с инфракрасной камерой показывает «Лицо», машина только
со сканером — «Отпечаток». Нарисовать лицо на машине без камеры значит заставить человека
ждать запрос, который никогда не появится.

**Везде, где спрашивают пароль, биометрический запрос начинается сам** — экран входа, окно
повторной проверки перед настройками и проверки на входе в отдельные модули. Ничего нажимать
заранее не нужно. Если на этой машине биометрия недоступна или у этого хранилища нет
биометрической привязки, запрос не появляется вовсе и сразу открывается вкладка пароля: ни
сообщения об ошибке для функции, которую вы никогда не настраивали, ни заведомо обречённого
запроса Hello.

Windows Hello не позволяет приложению выбирать, *какой* способ запрашивать — это решает
система по тому, что вы зарегистрировали. Цепочка определяет, что Tessera показывает, какой
фактор запускает автоматически и на что переходит при отказе.

## Ключ восстановления — обязательно прочитайте

Ключ восстановления показывается **один-единственный раз**, во время настройки.
Сохраните его в надёжном месте и *не* рядом с зашифрованными файлами.

Если вы потеряете пароль, потеряете телефон с аутентификатором, а машина с привязанным
отпечатком выйдет из строя — ключ восстановления останется единственным способом
входа. Если и он потерян, **файлы восстановить невозможно.** Это заложено в дизайн,
а не баг.

## Повседневное использование

- **Шифрование** — выберите один или несколько файлов, выберите алгоритм, нажмите
  «Зашифровать». Для одного файла откроется диалог «Сохранить как»; для нескольких
  файлов будет запрошена целевая папка, и для каждого запишется `<имя>.ivault`. Ошибка
  в одном файле не прерывает обработку остальных; в конце вы получите сводку.
- **Удаление оригинала** — по умолчанию выключено, чтобы вы не потеряли данные
  случайно. Но шифрование бессмысленно, если открытый текст всё ещё лежит рядом с
  зашифрованным, поэтому отметьте **безопасно удалить оригинал после шифрования**,
  когда цель — секретность. Такое удаление сначала перезаписывает файл случайными
  байтами и минует Корзину. (В меру возможного: выравнивание износа SSD означает, что
  это не гарантия против криминалистического восстановления.)
- **Поиск остатков** — после шифрования приложение ищет оставшиеся незашифрованные
  копии: резервные копии редакторов (`~$…`, `.bak`, `.wbk`, папки автосохранения WPS)
  и одноимённые копии в других местах на диске. Элементы, связанные с исходным файлом,
  отмечены заранее; совпадения по имени по всему диску **никогда** не отмечаются
  заранее, так как одно из них может оказаться файлом, который вы хотели сохранить.
  Вы можете перезапустить это в любое время для файла `.ivault`.
- **Блокировка** — закрытие окна прячет приложение в трей. Разблокированный
  мастер-ключ существует только в памяти backend-процесса и исчезает вместе с ним.

## Очистка компьютера

Пять панелей в разделе **Очистка ПК** на боковой панели. Они работают с правами обычного
пользователя; только несколько операций запрашивают права администратора, и тогда
появляется небольшой вспомогательный процесс, который делает эту одну работу и
закрывается. Сама Tessera никогда не работает от имени администратора — она держит
расшифрованный ключевой материал, и долгоживущий процесс с повышенными правами, который
его хранит, был бы куда более ценной добычей, чем обычный.

### Проверка

Одна кнопка запускает девять проверок сразу и показывает каждую, как только та готова. На
обычной машине первые результаты появляются заметно быстрее секунды; запланированные
задачи занимают от пяти до девяти секунд и приходят последними, потому что процесс без
повышенных прав не может быстрее — Windows не даёт ему даже перечислить папку.

Две вещи намеренно вынесены под собственную кнопку, а не включены в эту проверку: анализ
хранилища компонентов и измерение каждой папки первого уровня на системном диске. Каждая
занимает около минуты, и включение их в проверку одной кнопкой превращало её в
двухминутное ожидание.

В разделе **Параметры проверки** задаётся, сколько времени к файлу не должны были
обращаться, чтобы он считался мусором. По умолчанию сутки — намеренно осторожно: идущая
установка пишет во временную папку. На только что перезагруженной машине значение *Любой
давности* обычно находит в несколько раз больше.

### Место на диске

- **Системный диск** — файл гибернации, хранилище компонентов, точки восстановления,
  `Windows.old` и то, что занимает файл подкачки. Последний показан только для сведения и
  не выбирается: без него программы будут падать при нехватке памяти, а не замедляться.
- **Большие файлы** — самые крупные сначала, в выбранных вами папках и крупнее выбранного
  размера.
- **Место по папкам** — какие папки занимают место, по одному уровню за раз.
- **Дубликаты** — сравниваются по размеру, затем по выборке из начала и конца каждого
  файла, затем целиком. В каждой группе копия с самым коротким путём сохраняется за вас,
  остальное отмечено заранее.
- **Диски** — оптимизация сначала читает тип носителя. Tessera отказывается
  дефрагментировать SSD, даже если её об этом попросить: выигрыша нет, а износ есть.

### Автозапуск и меню

Всё, что стартует при входе, собрано из четырёх мест: реестра, папки автозагрузки,
запланированных задач и служб. Инструменты, читающие только реестр, показывают горстку
записей, тогда как машина по-прежнему загружается минуту.

Здесь ничего не удаляется. Записи реестра переносятся в резервный ключ, ярлыки автозагрузки
переименовываются, запланированные задачи отключаются через планировщик, а службы
переводятся на ручной запуск, а не отключаются — отключение одной ломает запуск всего, что
от неё зависит. Каждая возвращается одним щелчком.

Блокировщик всплывающих окон работает на двух уровнях: отключает то, что их порождает при
запуске, и закрывает через `WM_CLOSE` окна, подходящие под правило. Он никогда не завершает
процесс, никогда не трогает окно, в котором вы работаете, и записывает всё, что закрыл.

### Установленные программы

Всё установленное, прочитанное из трёх мест реестра — 64-битного, 32-битного и
пользовательского. Чтение только первого теряет больше половины.

Размеры измеряются по папке установки, а не берутся из того, что заявил установщик.
Удаление запускает собственную программу удаления; Tessera никогда не удаляет папку
установки сама — после этого остались бы службы, драйверы и записи реестра.

Вкладка реестра прямо говорит, что очистка устаревших ссылок **не ускорит ваш ПК**. Это
имеет смысл ради порядка. Единственная категория, которая действительно помогает, —
регистрации компонентов, указывающие на исчезнувшие DLL.

### Инструменты

Восемнадцать небольших утилит, у каждой строка о том, когда она понадобится: очистить кэш
DNS, посмотреть, какая программа заняла порт, выяснить, что держит файл, перезапустить
Проводник, пересобрать кэш значков, найти пустые папки, найти слишком длинные пути,
переименовать пакетно с предварительным просмотром.

Файл hosts показывается только для чтения. Его правка позволяет перенаправить любой сайт,
а это не та возможность, которой зашифрованное хранилище должно распоряжаться от вашего
имени.


## Синхронизация между устройствами

Ваш телефон, планшет и этот ПК разделяют один буфер обмена и одну точку приёма файлов.
Скопируйте формулу на телефоне — вставьте её в Word на ПК. Бросьте видео на 4 ГБ на ПК —
заберите его на планшете. Ничего не проходит через сервер: устройства общаются напрямую по
вашей локальной сети со сквозным шифрованием.

### Сопряжение устройства

Откройте **Между устройствами → Добавить устройство** и выберите:

- **Показать мой код** — появится QR-код. Отсканируйте его с другого устройства.
- **Ввести код с другого устройства** — вставьте код, который оно показывает.
- **Устройства рядом** — список несопряжённых устройств в этой сети. Выберите одно и выполните
  сопряжение, не передавая никакого кода. Имена помечены как *не проверено*: имя устройства —
  это то, что ввёл его владелец; личность подтверждает именно сверка кода безопасности ниже.
- **Ввести адрес** — запасной путь, когда не работает ничего другого, и самый надёжный. На
  вкладке показан адрес этого компьютера (`192.168.1.7:52140`), который надо продиктовать, и
  поле для адреса собеседника. Укажите `IP:порт` или только IP: в последнем случае Tessera
  спрашивает у маяка обнаружения устройства его текущий порт. Два устройства, которые видят друг
  друга по IP, свяжутся этим способом: одна подсеть не нужна, и он работает там, где
  заблокирована многоадресная рассылка.

**Если список устройств рядом остаётся пустым, нажимайте «Просканировать сеть», а не «Обновить»
ещё раз.** Обновление лишь перечитывает уже услышанное, а многие роутеры отбрасывают
многоадресные пакеты, на которых держится автоматический поиск: в таких сетях сто обновлений
ничего не покажут. Сканирование напрямую опрашивает каждый адрес подсети и обходит проблему.

Жёлтая полоса вверху страницы означает, что брандмауэр Windows блокирует службу синхронизации и
другие устройства не видят этот компьютер. Нажмите **Разрешить** — одно повышение прав, и правило
охватывает все сетевые профили Windows, но только программу синхронизации Tessera: она отвечает
лишь на запросы обнаружения и зашифрованное QUIC-согласование, а без сопряжения ничего прочитать
нельзя. Windows отбрасывает такие пакеты молча: ни ошибки, ни записи в журнале, только пустой
список, — поэтому об этом стоит сказать прямо, а не оставлять человека гадать. **Проверка связи**
под списком проходит по каждому шагу — приём подключений, адреса, объявление, порт ответа,
обнаружение, активное сканирование — и говорит, какой из них не проходит и что делать.

Затем на обоих экранах появятся одни и те же шесть цифр и шесть эмодзи. **Сверьте их.** Если
совпадают — подтвердите с обеих сторон; если различаются, между вами кто-то есть — выберите
«Не совпадают», и сопряжение будет прервано. Код сопряжения действует ровно один раз и истекает
через минуту, поэтому старый снимок экрана никому не пригодится.

При сопряжении вы выбираете, что это за устройство:

| | Постоянное | Временное |
|---|---|---|
| Для чего | Ваши собственные устройства | Чужие — друга, компьютер в аудитории |
| Автоматическое переподключение | Да | Нет |
| Синхронизация буфера обмена | Да | Нет |
| Истекает | Никогда, пока вы не отзовёте | 10 мин / 30 мин / 1 час / 1 день |
| Учётные данные на диске | Хранятся в зашифрованном виде | Вообще не записываются |

Отозвать любое устройство можно в любой момент. Отзыв действует немедленно и окончательно:
старые учётные данные перестают работать при следующей же попытке подключения, а не после
перезапуска.

### Копирование и вставка

Всё, что вы копируете, уходит на ваши постоянные устройства и попадает прямо в их системный
буфер обмена — можно сразу вставлять. Обычный и форматированный текст, а также изображения идут
в представлении, которое умеет использовать принимающее приложение; формулы и физические символы
остаются нетронутыми: `E = mc²`, `m/s²`, `θ̇`, `∑∫√`. Синхронизируется только самый новый элемент
буфера: старая копия не придёт позже и не заменит только что скопированное. Windows проверяет
каждые 200 мс; в Android 10 и новее система разрешает Tessera читать буфер только на переднем
плане, поэтому после копирования в другом приложении Android один раз откройте Tessera для
синхронизации. Полученное содержимое всё равно записывается в буфер Android.

Крупные изображения не проталкиваются: другое устройство скачает их, только если вы
dействительно вставите.

### Отправка файлов

Выберите одно или несколько устройств в списке и нажмите **Отправить файлы**. Можно явно
выбрать одного или нескольких получателей; файлы, папки, изображения и пакеты приложений
помечаются в списке передач. У каждого устройства своя независимая передача: медленный телефон
никогда не тормозит быстрый ПК, а отказ или сбой одного не отменяет остальные.

Каждая активная передача показывает имя, прогресс, скорость и расчётное оставшееся время. С обеих
сторон её можно поставить на паузу, продолжить или отменить. Пауза сохраняет уже проверенные
полученные блоки; после обрыва или переподключения передача продолжается с этого места, а не
начинается заново. Каждый файл проверяется по прибытии — передача, не прошедшая проверку,
помечается как неудачная, а не как «готово».

Полученные исполняемые файлы (`.exe`, `.msi`, `.apk`) сохраняются как обычные файлы. Tessera
никогда не запускает и не устанавливает то, что получает.

### Как связь держится сама

Устройства, которые пропали — телефон заблокирован, ноутбук уснул, переключился Wi-Fi,
перезагрузился роутер — возвращаются сами. Кнопки «переподключиться» нет, и заново сканировать
ничего не нужно.

Переподключение пробует все маршруты одновременно (последний удачный адрес, ранее виденные
адреса и то, что сейчас сообщает обнаружение в локальной сети) и оставляет тот, который ответил
первым. В локальной сети это обычно занимает заметно меньше секунды. Поскольку обнаружение
работает вживую, устройство, сменившее IP-адрес — новый Wi-Fi, новая аренда DHCP, другая
подсеть — всё равно будет найдено.

### Что входит в эту сборку

Часть для Windows готова и включена в этот выпуск: служба синхронизации упакована внутрь exe и
запускается вместе с приложением.

**Приложение Android собрано из того же ядра протокола**, скомпилированного в нативную
библиотеку (`tesseracore.aar`) через `gomobile bind`: сопряжение, шифрование, конечный автомат
переподключения и возобновляемая передача — это буквально тот же код, что работает в Windows, а
не переписанная заново копия, которая рано или поздно разойдётся. Сторона Android добавляет
только то, что действительно específично для платформы: службу переднего плана, чтобы процесс
оставался живым, блокировку multicast Wi-Fi, чтобы обнаружение mDNS продолжало работать при
выключенном экране, и чтение/запись системного буфера обмена.

Перечисление сетевых интерфейсов — одна из тех вещей, что зависят от платформы. Android
блокирует системный вызов, которым для этого пользуется стандартная библиотека Go, поэтому
Android-клиент читает список интерфейсов через Java API и передаёт его общему ядру до запуска
узла, а затем всякий раз при смене сети. Без этого шага все пути обнаружения — устройства
поблизости, сканирование локальной сети, собственный адрес устройства для ручного сопряжения —
возвращались бы пустыми, и ничто не объясняло бы почему. Проверка соединения в разделе
**Устройства поблизости** по той же причине первым делом сообщает число интерфейсов: это первое,
что стоит исключить.

Экран собран из сворачиваемых разделов. То, чем вы сейчас не пользуетесь — код сопряжения,
обновления, блокировка приложения, журнал сбоев, — сворачивается в одну строку заголовка и
остаётся свёрнутым в следующий раз. Список сопряжённых устройств и действия отправки не
сворачиваются: ради них экран и существует. Доступны и метрики в реальном времени — устройств в
сети, задержка канала, текущая скорость, итоги сеанса, порт прослушивания, локальные адреса,
доступные интерфейсы — они читаются из уже приходящего потока событий, поэтому ничего не
опрашивается дополнительно, а таймер вовсе не работает, пока раздел закрыт.

Клиент Android поддерживает сопряжение сканированием QR-кода, сверку кода безопасности, список
устройств, приём и отправку буфера обмена, выбор одного или нескольких адресатов для файлов,
управление передачами и выбор папки для полученных файлов. Он также позволяет выбрать и отозвать
сразу несколько сопряжённых устройств. Близкие устройства, которые уже сопряжены и находятся в
сети, явно показаны в этом состоянии — повторное сопряжение не предлагается. Распознавание кодов
использует встроенную модель, а не загружаемую: сканирование для сопряжения чаще всего происходит
на только что установленном телефоне, ещё не подключённом к сети, — именно тогда модель,
скачиваемая при первом использовании, недоступна.

Приложение Android также проверяет собственные обновления по релизам этого репозитория.
Автоматическая проверка включена по умолчанию: она выполняется один раз при запуске и спрашивает
вас, только если более новая версия действительно есть. Если её выключить, ничего не проверяется,
пока вы не нажмёте **Проверить обновления**. Автоматична только *проверка*: Android не позволяет
установленному в обход магазина приложению молча поставить пакет, поэтому последним шагом всегда
остаётся системное окно установки, которое подтверждаете вы сами. Загрузка принимается только с
github.com, а совпадение ключа подписи нового пакета с уже установленным обеспечивает система.

Он собран и подписан, но **не** запускался здесь на реальном устройстве, поэтому первую
установку считайте пробной.

### Безопасность

У каждого устройства своя долговременная пара ключей, создаваемая при первом запуске и хранимая
в Windows DPAPI — никогда не серийный номер оборудования, IMEI или MAC-адрес, потому что их
нельзя отозвать. Нахождение в одной сети не даёт ничего: каждое соединение заново сверяет
личность с тем ключом, который вы подтвердили при сопряжении, а устройство с внезапно
изменившимся ключом отклоняется явно, а не принимается втихую.

Каждое соединение согласовывает новые одноразовые ключи, поэтому запись сегодняшнего трафика и
последующая кража ключа устройства всё равно не позволят его расшифровать. Пути входящих файлов
проверяются до любой записи — выходы через `../`, абсолютные пути и зарезервированные имена
Windows отклоняются сразу.

### Как связать устройства

На компьютере откройте **Между устройствами → Устройства и синхронизация → Создать код
сопряжения**; на телефоне нажмите **Сканировать для сопряжения** и наведите на QR-код. Затем
на обоих экранах появятся одни и те же шесть цифр и шесть эмодзи — убедитесь, что они
совпадают, подтвердите с обеих сторон, готово.

Обе стороны могут выбрать папку для полученных файлов, а переименование устройства
расходится по всем сопряжённым примерно за десять секунд и не требует переподключения.

Если сканирование словно зависает, обычная причина — устройства в разных сетях либо на Wi-Fi
включена изоляция клиентов (частое дело в офисах, кампусах и отелях). Быстрее всего проверить
через раздачу Wi-Fi с телефона. Полное руководство:
[руководство по подключению](modules/file_vault/crossdevice/docs/06-连接指南.md).

### Ход передачи

Как только передача начинается, появляется карточка прогресса: имя файла, устройство-получатель,
проценты, переданные байты из общего объёма — по строке на файл. Она обновляется раз в 250 мс,
а не на каждый блок: блок — это 4 МБ, на гигабите их десятки в секунду, и перерисовка на каждый
блок заставляет полосу дёргаться, а не двигаться.

### Журнал диагностики

У журнала диагностики есть собственный пункт в панели навигации, и тот же журнал доступен в
настройках — один переключатель, одно содержимое, попасть можно с любой стороны. **По умолчанию
он выключен.** Включённый, он
записывает только сбои: не сработавшее сочетание клавиш, недоступное устройство,
не запустившуюся службу. Он никогда не записывает, что вы делали: ни буфер обмена,
ни имена файлов, ни пути, ни ключи.

Он намеренно не зашифрован: случай, которому журнал нужнее всего, — это когда хранилище
не открывается, и зашифрованный журнал именно тогда прочитать нельзя. По этой же причине
он обязан быть выключен по умолчанию. Одна кнопка стирает всё.

### Что нужно для соединения

Оба устройства должны быть в одной локальной сети — один и тот же Wi-Fi либо компьютер по
Ethernet за тем же роутером. Больше ничего не требуется: ни учётной записи, ни облака, ни
проброса портов.

Порт прослушивания не фиксирован. Если порт по умолчанию занят, служба берёт назначенный
системой; и код сопряжения, и запись mDNS сообщают тот порт, который реально используется, так
что дальше это никого не волнует.

VPN или прокси на компьютере не мешают: при объявлении адресов пропускаются интерфейсы без
multicast (а VPN-туннель — именно такой), поэтому телефон никогда не получит адрес туннеля,
до которого не может достучаться.

Чего приложение обойти не может — это **изоляция клиентов Wi-Fi**: во многих корпоративных,
университетских и гостиничных сетях устройствам в одном Wi-Fi запрещено общаться между собой.
Раздача Wi-Fi с телефона — самый быстрый способ и убедиться в этом, и обойти.


## Модель безопасности

Двухуровневое конвертное шифрование:

```
                     ┌─ пароль ─────────────┐
                     ├─ код из письма ──────┤
Мастер-ключ          ├─ TOTP ───────────────┤  каждый оборачивает IMK независимо
идентичности (IMK) ──┼─ Windows Hello ──────┤
                     └─ ключ восстановления ┘
                          │
                          ▼
   ключ на файл (FK), новый для каждого файла, шифрует содержимое блоками
   затем FK оборачивается IMK и хранится внутри заголовка .ivault
```

- Слоты пароля и ключа восстановления получают ключ-обёртку через **scrypt с
  N=2¹⁷, r=8** (текущий минимум по рекомендации OWASP): около 134 МБ ОЗУ на каждую
  попытку подбора — именно это делает ферму GPU или ASIC бессмысленной: тысячи
  параллельных ядер бесполезны, если каждому нужны свои 134 МБ. Каждый слот хранит
  ту стоимость, с которой был запечатан, поэтому её повышение никогда не запирает
  уже существующее хранилище: слот, оставшийся на прежней стоимости, молча
  переупаковывается при следующей разблокировке.
- Все соли и все ключи создаются на машине самого пользователя (`os.urandom`) при
  первоначальной настройке — **в exe не зашито никаких секретов**, поэтому одна и та
  же загрузка в тысяче рук даёт тысячу никак не связанных хранилищ.
- Уровень идентичности (обёртка IMK, слоты ключей) всегда AES-256-GCM; выбор
  алгоритма влияет только на содержимое файлов.
- Базы данных буфера обмена / заметок / истории ИИ используют SQLCipher с ключом,
  выведенным через HKDF из IMK — не нужно запоминать второй пароль, но они
  нечитаемы, пока хранилище заблокировано.
- Процесс рендеринга не имеет доступа ни к Node, ни к файловой системе
  (`contextIsolation: true`, `nodeIntegration: false`); он может обращаться к backend
  только через узкий preload-API.
- **Разблокировка достаточна по любому одному фактору**, поэтому общая стойкость
  равна стойкости самого слабого фактора. Утёкший пароль сводит на нет остальные
  четыре. Одновременное требование нескольких факторов в этой версии не
  поддерживается.

## Где хранятся ваши данные

| Что | Где |
|---|---|
| Идентичность, базы данных хранилища, вложения | `%LOCALAPPDATA%\Tessera\data` *(настраивается — см. ниже)* |
| Seed TOTP, ключ email, пароль SMTP | Диспетчер учётных данных Windows |
| Разблокированный мастер-ключ | Только память backend-процесса — никогда на диске |

> **Переходите со сборки под именем «Ideal1 File Vault»?** Хранилище переедет само. При первом запуске приложение ищет старую папку `%LOCALAPPDATA%\Ideal1 File Vault\` и переносит её тем же транзакционным способом, что и любой другой перенос: согласованные снимки SQLite, проверка и затем атомарное переименование, а **старая папка остаётся нетронутой**. Выбранное ранее в установщике произвольное расположение тоже сохраняется.

Ничего никуда не загружается. Единственные исходящие соединения — те, что вы сами
настраиваете: ваш собственный SMTP-сервер для кодов входа, выбранный вами
ИИ-эндпоинт, если используете ассистента, цели теста скорости и GitHub Releases для
проверки обновлений.

Данные идентичности привязаны к одному компьютеру и не переносятся автоматически.
`data/` в gitignore и никогда не коммитится.


### Где будет храниться хранилище

Расположение по умолчанию подходит большинству. Переместить его — на диск, который вы
действительно бэкапите, в зашифрованный том, на второй диск — можно тремя способами, по
убыванию приоритета:

1. **Переменная окружения `IDEAL1_FILE_VAULT_DATA_DIR`.** Важнее всего остального,
   действует только на этот запуск и отключает любой автоматический перенос: если вы её
   задали, значит этой папкой управляете вы.
2. **Установщик.** `Tessera.Setup.exe` спрашивает папку для данных на
   отдельной странице, сразу после вопроса о том, куда ставить программу. Это два разных
   решения: переустановить в другую папку легко, а перенести хранилище, которое вы
   наполняли полгода, — нет.
3. **Настройки → О программе → Изменить расположение.** Выберите папку и перезапустите.
   Перенос происходит при следующем старте, *до* того как что-либо откроет хранилище:
   копирование зашифрованной базы SQLite с открытыми соединениями молча потеряло бы то,
   что осталось в журнале упреждающей записи. Старая папка остаётся нетронутой, поэтому
   неудачный перенос ничего не стоит.

Удаление приложения никогда не удаляет папку с данными.

## Разработка

```
core/       общая инфраструктура: конфигурация, логирование, реестр модулей, обёртки для subprocess
modules/    подключаемые функциональные модули — одна папка = один самодостаточный сценарий
scripts/    точка входа CLI: run.py (list / run <module>)
docs/       заметки по архитектуре, спецификации, процедура релиза
tests/      дымовые тесты
```

Внутренние правила — полная версия в [`CLAUDE.md`](CLAUDE.md) и
[`modules/README.md`](modules/README.md):

- Python ≥ 3.9. Используйте `python -X utf8 …`, когда вывод не ASCII.
- Модули никогда не импортируют друг друга; они зависят только от `core/`. Общая
  логика выносится в `core/`.
- Модули могут сочетать JavaScript или C, вызываемые через `run_command()` из
  `core/proc.py`.

Добавление сценария: скопируйте `modules/_template/` → `modules/<name>/`,
отредактируйте `MODULE_META`, реализуйте, затем подтвердите через
`python scripts/run.py list`.

```bash
python -m pytest tests/                        # дымовые тесты
python -m pytest modules/file_vault/tests/     # набор тестов хранилища
cd modules/file_vault/ui && npm run lint       # линт UI
```

Подробнее: [`docs/architecture.md`](docs/architecture.md) ·
[`modules/file_vault/README.md`](modules/file_vault/README.md)

## Сборка релиза

Сборка должна выполняться на **Windows x64** — PyInstaller не является кросс-
компилятором.

```powershell
cd modules\file_vault\ui
npm install
npm run build:standalone
```

Это компилирует нативные C-хелперы, замораживает две цели PyInstaller, затем
запускает `tsc` + `vite build` + `electron-builder`, производя
`ui/release/<version>/` — both `Tessera.exe` (portable) and
`Tessera.Setup.exe` (installer).

Подписью занимается сама сборка: она создаёт сертификат при первом запуске, закрепляет его открытый ключ в `signer-policy.json`, хранит закрытый ключ в хранилище сертификатов как **неэкспортируемый** и пишет защищённую паролем резервную копию вне репозитория. Вручную здесь делать нечего. (`secure-signing-key.cmd` в корне репозитория может перезащитить эту копию вашей собственной парольной фразой, если хотите, чтобы она пережила потерю этой машины.)

Push тега `v*` запускает ту же сборку в CI — см.
[`.github/workflows/build-windows.yml`](.github/workflows/build-windows.yml). Workflow
загружает **неподписанный** exe в **черновой** релиз и на этом останавливается. Подпись
кода **намеренно** остаётся на вашей собственной машине: ключом, положенным в секреты CI,
сможет воспользоваться любой, кто способен изменить workflow, и подпись превратится в
чистую декорацию.

Перед публикацией собственного форка нужно заполнить два placeholder-а:

- `REPO` в `modules/file_vault/ui/electron/updateService.ts` → ваш `owner/repo`

Это единственное, что правится вручную. Сертификат подписи **создаётся сам** при первом
запуске `npm run build:standalone`, а отпечаток его открытого ключа записывается в
`signer-policy.json` — вам остаётся только закоммитить его. Каждая последующая сборка
заново проверяет, что сертификат, которым она собирается подписывать, — по-прежнему тот
самый закреплённый, и останавливается, если это не так: иначе пересборка на другой
машине молча выпустила бы версию, которую отвергают все установленные клиенты, и ничто
не выглядело бы подозрительным, пока пользователь не нажмёт «Обновить».

**Сертификат не обязан стоить денег.** Встраивание подписи внутрь exe и покупка
сертификата у удостоверяющего центра — две независимые вещи: формату Authenticode всё
равно, кто выпустил сертификат, а закрепление открытого ключа на стороне клиента на
самом деле *надёжнее*, чем доверие к УЦ: атакующему понадобится ваш закрытый ключ, а не
одноимённый сертификат от любого из сотен публичных УЦ. За деньги покупается репутация в
SmartScreen, то есть отсутствие предупреждения «Windows защитила ваш компьютер» при
первом запуске.

Если оставить `SIGNER_POLICY` пустым, приложение всё равно работает — оно просто
отказывается обновлять себя и прямо об этом сообщает.

Полная процедура, включая то, что делать при истечении срока сертификата, и объяснение,
почему в релизе ровно два файла:
[`docs/standalone-exe-release.md`](docs/standalone-exe-release.md)

## Лицензия

> **Обновлённый набор очистки.** Данные браузера разбиты по браузерам и профилям (куки, история, формы, данные сайтов); хранилища паролей и закладки никогда не показываются и не могут быть удалены отсюда. Старые пакеты драйверов, вытесненные новыми версиями, обычно самый большой мёртвый груз на системном диске. Пустые папки, битые ярлыки и файлы нулевого размера собираются с рабочего стола, из документов и загрузок. Программы сортируются по размеру *и* по времени простоя. Кнопка очистки находится вверху страницы, а не внизу. Каждая категория говорит, какого рода «пустоту» она нашла — действительно нечего чистить, заблокировано правами доступа или вообще не запускалась — и сколько мест она проверила.
