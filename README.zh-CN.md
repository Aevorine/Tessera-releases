**Tessera** —— 一个 Windows 上的多因素加密金库，同时带着密码管理、剪贴板历史、笔记、AI 助手和高速文件管理。
所有东西共用一次解锁；除非你自己配置，数据不会离开这台电脑。

> 状态：`0.1.7`，持续更新中。仅支持 Windows 10/11 x64 —— 指纹解锁、资源管理器
> 集成、文件全局快捷键这几项直接依赖 Windows API。

## 有什么功能

| 功能 | 说明 |
|---|---|
| **文件加密** | 任何文件加密/解密成单个 `.ivault` 文件。三档可选：**抗量子**（默认——内容仍是 AES-256-GCM，每个文件的密钥额外用 ML-KEM-1024 封装一层，要同时攻破两种构造才解得开）、经典 AES-256-GCM、ChaCha20-Poly1305。选的档位对「多选文件」和「整个文件夹」完全一样生效。支持一次多选批量处理。文件名和校验值放在**加密过的**头部里，所以拿到 `.ivault` 的人这两样都看不到。 解密侧有独立的「解密文件夹」入口，跟「解密文件」并排；打开一个加密文件夹时**不再先整包解密**——只读档案索引所在的那几百 KB，所以 10 GB 的文件夹和小文件夹一样快打开，解压时每个文件也只写一遍，不再把整棵树落两遍盘。 |
| **安全删除 + 明文残留扫描** | 加密后可选「覆写再删除」原文件；并扫描散落在别处的明文残留 —— Office/WPS 的自动备份、`~$` 临时文件、以及磁盘上其它位置的同名副本。 删整个文件夹时会走遍整棵树：只读文件（文件夹自带的 `desktop.ini`、从压缩包里还原出来的东西）会被清掉只读位再覆写，而不是让整趟清理就此中断；真正删不掉的（比如还在别的程序里开着）会把路径写进报错里。**没删掉的源文件绝不会被报成已完成。** |
| **密码管理** | 完整增删改查，默认打码；支持导入 Chrome/Edge/Firefox 导出的密码 CSV（导入后自动安全删除那份明文 CSV），也能导出成 Chrome/Edge 可读的格式。 恢复码导入可以在导入后安全删除源文件，**默认勾选**：那份文件里是明文的恢复码，导进加密库之后还留在下载目录里，这次导入就等于什么也没保护到。 |
| **剪贴板历史** | 加密入库，自动分类（网址/邮箱/电话/**公式**/代码/文本），置顶、搜索、虚拟滚动、应用黑名单、回收站、系统托盘，全局快捷键 `Ctrl+Shift+V` 呼出面板。点缩略图看原图（全屏或浮窗，可选），支持缩放、拖动、点图即复制。导出可选全部／只置顶／只隐藏／只勾选，勾选支持多选与全选；导入支持多选，并默认在导入后安全删除原文件。导入不会让已经有的内容多出第二份——内容相同的会并进已有那条，置顶和隐藏的标记一并保留。库里原本就有的重复，另有「清理重复项」先列出清单、确认之后才合并，被合并掉的进回收站随时可还原。 |
| **笔记** | Markdown 笔记，支持图片、分类、全文搜索，存在加密数据库里。分类可按名称、笔记数、最近使用排序，也可以自己拖成想要的顺序。列表上方有四个计数——总计、活跃、已隐藏、回收站——每一个都能点开它数的那批：点「已隐藏」就看那些笔记，点「回收站」就进回收站，再点一次回来。其中会让隐藏笔记出现在屏幕上的那两个会先要求验证身份，用的是和别处一样的解锁方式；被删进回收站的隐藏笔记同样留在这道验证后面，回收站会写明扣下了几条，免得列表变短看起来像丢了东西。每篇笔记都记住你上次读到、编辑到哪里，重新打开时直接回到那里，大到需要分段的笔记也一样。大笔记在毫秒级就能上屏，打字滚动也不卡：正文在后台线程上**逐块渲染**，首屏不等后面的部分——一份 4 MB 的笔记开头约 40 毫秒出现，而不是一秒半。 笔记可以在列表里多选或全选，一步移进某个隐藏分类；从文件夹批量导入时也能直接落进隐藏分类。分类可以一层套一层，隐藏区和可见区一样深。 |
| **AI 助手** | 对接任意 OpenAI 兼容接口（默认 DeepSeek）。模型列表实时从服务端拉取，并标出每个模型的发布日期、最新的排在最前，选之前就看得清；应用不认识的模型照样显示、照样能选，已停用的会标注出来而不是选了之后静默失败。选中后全应用的 AI 功能都用这个模型。支持导入「技能」文件，用的是和 Claude Code 相同的 `SKILL.md` 格式。对话历史加密存储。 |
| **文件管理** | 高速复制/剪切/粘贴/删除，与资源管理器剪贴板双向互通，带实时进度卡片；全局 `Ctrl+V` / `Delete` / `Shift+Delete` 接管。 |
| **电脑清理** | 五个面板，管的是保险库底下那台机器。「一键体检」同时扫垃圾文件、浏览器缓存、隐私痕迹、插件、开机自启、弹窗源头和失效的注册表引用，而且**哪一类先扫完哪一类先显示**，不是让你对着一块静止的屏幕等。「空间分析」包含 C 盘瘦身、大文件、目录占用、重复文件（先比体积、再比每个文件的头尾采样、最后才全量比对）和磁盘优化——对固态硬盘执行 TRIM 而不是碎片整理。「启动与右键」列出登录时会跑的一切（注册表、启动文件夹、计划任务、服务），加上右键菜单里的每一项，以及一个双层弹窗拦截：既让产生弹窗的东西根本别启动，也关掉漏出来的那些。「软件管理」列出机器上装的全部软件，「工具箱」收了四十二个小工具。清理动手之前可以先预演：走的是真实清理的同一条代码路径，但一个字节都不动，算出每块盘能腾出多少、有几项撤不回来。面板打开就是满的——先铺上次的结果、同时在后台重扫。你也可以加规则指向自己的文件夹（不能指向盘符根目录、系统目录或保险库自己的数据），让定时任务只看不删。浏览器数据按浏览器、按配置文件分项列出——Cookie、历史、表单、站点存储——而密码库和书签既不出现在列表里，也不可能从这里删掉。被新版本顶替的旧驱动包通常是 C 盘上最大的一块死重量，系统自带的磁盘清理完全不碰它们。桌面、文档、下载三处的空文件夹、指向已删除目标的快捷方式和零字节文件会一并收出来。已装软件同时按体积和闲置时间排——四个 G 只有在「而且我一年没打开过」之后才构成卸载的理由。清理入口在页面**最上面**而不是底部：一个圆环，扫之前写着「扫一扫」，扫完当场变成「立即清理 6.4 GB」，再加一条跟着你滚动的吸顶细条。每一类都会说清它找到的是哪一种「空」——确实没有可清理项、被权限挡住了、还是根本没跑起来——以及它为此检查了多少个位置。 |
| **能看出哪些动得、哪些动不得** | 每一条都带一个五级判断——Windows 要用 / 驱动 / 你在用的 / 可选 / 推广垃圾——并把理由写成一句人话。Windows 要用的那一级**锁死不可勾选**，而且就算前端把它传上来，后端也会拒绝。**认不出来的一律判成「可选」，绝不判成垃圾**：漏清一个缓存文件的代价是几十 MB，误删一个驱动的代价是一下午。 |
| **删掉的都能拿回来** | 缓存和临时文件是直接删的——空间就是这么腾出来的。**你自己的文件进回收站。** 注册表项、自启项、右键菜单项是「禁用 + 备份」，不是删除，每一条都能一键还原。动注册表之前先导出 `.reg` 备份，**导出失败就一条都不改**。 |
| **网络测速** | 跑测速、看趋势图、留历史记录。 吞吐量的读法跟公开测速站一致：按四分之一秒切片采样，取稳态段的 **90 分位**，于是 TCP 慢启动的爬坡段和偶发的一次深坑都不会把数字拖到这条线真实能力之下。延迟量的是一次 TCP 往返而不是一整个 HTTPS 请求，服务端自己的处理时间因此不会算进来；抖动取相邻两次采样的平均变化量——通话和游戏卡不卡，取决的正是这个量。每次结果还附一个**稳定度**，说明这次测量里快慢时刻差了多少倍，也就回答了"下次测出来的数不一样，到底有没有意义"。 |
| **带签名的自动更新** | 一个 release 里**有两个文件：安装包和免安装版各一个**。信任根是 exe 内嵌的 Authenticode 签名，对照构建时写死的发布者名与公钥指纹校验 —— 所以一张免费的自签名证书就够了，花钱买 CA 证书只能多消掉一个 SmartScreen 提示。没签名、被篡改、或换了密钥签的下载会被直接删掉；没配签名者的构建拒绝一切更新，绝不「没配置就放行」。同一形态出现两个构建时宁可报错也不猜。安装是事务式的：主进程退出后再验一次签名，旧 exe 保留，新版本起不来或起来了但卡住会自动回滚。金库、登录信息和设置都不在 exe 里，更新全程不碰。 |
| **跨设备同步** | 手机复制，电脑粘贴，反过来也一样。文本、富文本、代码、数学公式和物理符号都不会变形，图片也能传。任意文件和文件夹可以发给一台或同时发给多台，支持断点续传，全程端到端加密。四种配对方式——扫二维码、粘贴配对码、从附近设备列表里点，或者手动输入地址——都是十秒左右的事。附近列表空着时，主动扫描能找到组播发现够不着的设备，连接诊断会直接指出卡在哪一步。 安卓端接入系统分享菜单：在任意应用里长按图片或文件 → 分享 → 选 Tessera → 选发给哪些已配对设备。文件发给你明确选中的设备（一台或多台，每次传输前自己定），剪贴板则始终同步到所有已配对设备。配对过一次之后，设备重新出现在网络里会自动连回来，通常一两秒，不需要点任何按钮——而且配对只需要做这一次：已配对的设备换个网络、换了 IP 也能自己重新找到对方，不依赖很多路由器会直接丢掉的组播发现。 |
| **界面与外观** | 全部界面共用一套设计语言——同一种页面标题、同一种分区卡片、同一套状态色，没有哪一屏看着像后来硬加上去的。八种强调色、两套视觉风格（原生增强 / 东方科技轻奢）、跟随系统/浅色/深色，以及「简洁」和「专业」两种模式来收起或展开诊断信息。安卓端用同一套配色和同一种分区排布。 |
| **6 种语言** | 中文、English、Français、Español、Русский、العربية，任意界面可切换，登录页也能切。 |

五种解锁方式，**任意一种通过即可进入**：密码 · 邮箱验证码 · 验证器动态码（TOTP）·
Windows Hello · 一次性恢复密钥。

这里的 Windows Hello 指的是**你在系统里设了哪种就用哪种——人脸、指纹或 PIN 都算**。
弹出来的是系统自己的验证框，所以一台有 Hello 摄像头、没有指纹传感器的电脑照样刷脸解锁。

登录页**默认就停在 Windows Hello，并且一打开就自动发起验证**，不用先点一下。如果这台机器
没给这个保险库绑过 Hello，它会静默切到密码框、不弹任何报错——试这一次不会有任何代价。

## 开始使用

### 方式一 —— 直接下载发布版

[Releases](../../releases) 页面有两个构建，是同一个应用，按你的习惯挑一个。

| | `Tessera.Setup.exe` | `Tessera.exe` |
|---|---|---|
| | **安装版** | **免安装版** |
| 装在哪 | 你自己选 | 文件放哪就在哪 |
| 开始菜单 / 桌面快捷方式 | 有 | 没有 |
| 出现在「应用和功能」里 | 是 | 否 |
| 需要管理员权限 | 不需要（按用户安装） | 不需要 |
| 能从 U 盘直接跑 | 不能 | 能 |
| 自动更新失败时能回滚 | 不能 | 能 |

两种都不会往你的用户目录之外写任何东西。**卸载不会删除你的金库** ——
见[数据存在哪](#数据存在哪)。

> 首次运行时 Windows 会弹「已保护你的电脑」。那是 SmartScreen 对自签名证书的反应，
> 不是病毒警告。点**更多信息 → 仍要运行**即可。只在第一次出现，应用内更新不会触发。

两种形态都能自动更新，各自更新各自的形态。

### 方式二 —— 从源码运行

```bash
git clone <这个仓库>
cd Tessera

# Python 侧 —— 运行时依赖已全部声明在 pyproject 里
pip install -e .

# 前端侧（node_modules 没有提交进仓库）
cd modules/file_vault/ui && npm install && cd ../../..

# 启动
python scripts/run.py run file_vault
```

最后这条命令实际是在 `ui/` 目录跑 `npm run dev`，拉起 Vite 开发服务器 + Electron
窗口；Electron 主进程会 spawn `backend_server.py` 作为常驻的 Python 子进程，通过
stdin/stdout 上的 NDJSON 协议通信，关窗口时一并结束。

可选 —— 指纹解锁需要 Windows Hello 的 Python 绑定：

```bash
pip install winrt-Windows.Security.Credentials.UI winrt-Windows.Foundation
```

## 首次运行：设置向导

第一次启动会自动弹出设置向导，依次是：

1. **设置密码** —— 用它包裹你的身份主密钥。
2. **绑定验证器 App** —— 扫码，输一次动态码确认。
3. **绑定指纹解锁** —— 这台电脑没配 Windows Hello 的话**自动跳过**。
4. **配置邮箱** —— 这一步可跳过，之后在设置页里补。详见下一节。
5. **生成恢复密钥** —— 只显示这一次，务必抄下来。

之后每次启动先进登录页，任意一种方式通过即可。

## 配置邮箱验证码登录

这是「往邮箱发一个 6 位验证码」的解锁方式。它是**用你自己的邮箱、走你自己的 SMTP
账号**发信 —— 中间没有任何 Tessera 的服务器，这也是为什么需要你填 SMTP 凭据。

### 第一步 —— 去邮箱服务商拿一个「应用专用密码 / 授权码」

基本上不能直接用你平时登录的密码。各家都要求第三方客户端用专门的应用密码或授权码：

| 服务商 | 在哪拿 |
|---|---|
| **Gmail** | 先开启两步验证，然后 Google 账号 → 安全性 → 应用专用密码。会得到一串 16 位字符；Google 显示时带的空格只是为了好读，**不是**密码的一部分。「不够安全的应用访问权限」已于 2022 年下线，所以只能用应用密码（或 OAuth）。 |
| **QQ 邮箱** | 设置 → 账号 → 开启 POP3/IMAP/SMTP 服务，然后生成**授权码**。填授权码，不是 QQ 密码。 |
| **163 邮箱** | 设置 → POP3/SMTP/IMAP → 开启服务并设置**授权码**。同理。 |
| **Outlook.com / Microsoft 365** | **不支持。** 微软已于 2026 年停用 SMTP AUTH 的基本认证，这类账号现在必须走 OAuth 2.0（XOAUTH2），本应用没有实现。请换一个邮箱收验证码，或者用另外四种解锁方式。 |

### 第二步 —— 填设置

在设置向导的「邮箱与发信设置」这一步，或者之后在
**设置 → 更新邮箱与发信设置** 里：

| 字段 | 含义 | 常见取值 |
|---|---|---|
| 恢复邮箱地址 | 验证码发到哪（可以和发信邮箱是同一个） | `you@example.com` |
| SMTP 服务器 | 服务商的发信服务器 | `smtp.gmail.com` · `smtp.qq.com` · `smtp.163.com` |
| SMTP 端口 | SSL 用 `465`，STARTTLS 用 `587` | `465` 或 `587` |
| 发信账号 | 用来发信的完整邮箱地址 | `you@qq.com` |
| 应用专用密码 | 第一步拿到的那个 —— **不是**登录密码 | 16 位应用密码 / 授权码 |
| 使用 SSL | 端口 **465** 勾上；**587**（STARTTLS）不要勾 | — |

> 在设置页里，密码字段留空表示「保持当前已保存的那个不变」。

### 第三步 —— 发一封测试邮件

点**发送测试邮件**，确认真的收到了。收不到的话错误信息会原样显示出来 —— 最常见的
原因是端口和 SSL 勾选不匹配、填了登录密码而不是应用密码，或者账号还没开启 SMTP 服务。

### 登录时是怎么用的

在登录页选**邮箱**标签，请求验证码。验证码 6 位、**10 分钟**内有效、**只能用一次**，
并且只存在于后端进程的内存里 —— 从不写到磁盘上。

## 配置验证器 App

用 Google Authenticator、Microsoft Authenticator、Authy 或任何标准 TOTP App 扫描
向导里的二维码，再输入当前显示的 6 位动态码确认绑定。扫不了码的话也可以手动输入
密钥。种子存在 Windows 凭据管理器里，不在仓库里。

## 配置生物识别解锁

这一项调用的是真实的 Windows Hello 传感器。需要装上面那两个 `winrt-*` 包，并且这台
电脑配置过 Windows Hello。没有的话向导会自动跳过这一步，不影响其余四种方式。

Tessera 会先问 Windows 这台机器实际装了哪些生物识别传感器，按 **人脸 → 指纹 → 虹膜**
的顺序选第一个可用的，标签和图标跟着真实硬件走：有红外摄像头就显示「人脸识别」，只有
指纹传感器就显示「指纹」。在一台没有摄像头的机器上画一张人脸，只会让人一直等一个永远
不会出现的提示。

**所有要密码的地方都会自动发起生物识别**——登录页、设置前的重新验证弹窗、以及各模块
自己的进入验证，都不需要你先点一下。这台机器用不了生物识别、或者这个金库没绑定过时，
不会弹任何提示，直接落到密码那一栏：既不会为一个你从没设置过的功能弹红框，也不会弹一次
注定失败的 Hello 提示。

Windows Hello **不允许应用指定用哪种方式**验证，具体弹什么由系统按你录入过的内容决定。
这条链决定的是界面显示成什么、自动发起哪一个、以及失败后往哪里回落。

## 恢复密钥 —— 这段务必看完

恢复密钥在设置时**只显示一次**。请存到安全的地方，而且**不要**和加密文件放在一起。

如果你忘了密码、装验证器的手机丢了、绑过指纹的这台电脑又坏了 —— 恢复密钥就是唯一
还能进去的路。如果连它也丢了，**文件将无法恢复**。这是设计使然，不是 bug。

## 日常使用

- **加密** —— 选一个或多个文件，选算法，点加密。单选时弹「另存为」精确指定文件名；
  多选时让你选一个目标文件夹，每个文件按 `原名.ivault` 存进去。中间某个文件失败不会
  中断其余的，最后汇总告诉你几个成功几个失败。
- **删除原文件** —— 默认**不删**，避免意外丢数据。但如果原文件还躺在密文旁边，那加密
  就形同虚设 —— 别人根本不用解锁，直接打开原文件就行。所以目的是保密的话，务必勾上
  **加密后安全删除原始文件或原始文件夹**。这个删除是先用随机字节覆写、再删除，不进回收站。选的是文件夹时，里面每个文件都会被逐个覆写，然后整棵目录树一起删除；不跟随链接，所以文件夹以外的东西一律不动。
  （尽力而为：SSD 的磨损均衡意味着这不是对抗专业取证的保证。）
- **明文残留扫描** —— 加密完成后自动扫描散落的明文：编辑器备份（`~$…`、`.bak`、
  `.wbk`、WPS 自动备份目录）以及磁盘上其它位置的同名副本。与源文件相关的项默认勾选；
  「磁盘同名副本」**一律不默认勾选** —— 里面可能有你要保留的正式原件。也可以随时选一个
  `.ivault` 文件事后重新扫。
- **锁定** —— 关闭窗口是隐藏到托盘。解锁后的主密钥只存在于后端进程内存里，随进程结束消失。

## 清理这台电脑

侧边栏「电脑清理」下的五个面板。它们**以普通用户权限运行**；只有少数几项要管理员权限，
那时会拉起一个小助手进程，干完那一件事就退出。Tessera 自己永远不提权运行——它手里握着
解密后的密钥材料，一个长期提权的进程一旦被攻破，损失远比普通进程大。

### 体检与清理

一个按钮同时扫九类，扫完一类显示一类。本机实测第一批结果在**一秒以内**上屏；计划任务要
五到九秒、排在最后，因为非提权进程拿不到更快的路——Windows 连列出那个目录都不允许。

有两件事**刻意没有放进那次扫描**，各自单独一个按钮：分析组件存储、以及走遍系统盘每一个
一级目录。两者各要一分钟左右，放进「一键体检」会把它变成两分钟的等待。按钮上写着大概要多久。

「扫描选项」里可以设「多久没动过才算垃圾」。默认一天，是刻意保守的——正在进行的安装会往
临时目录写东西，删掉那些文件可能让它崩掉。刚重启过的机器上把它改成「不看时间」，通常能多
清出好几倍。

### 空间分析

- **系统盘** —— 休眠文件、组件存储、还原点、`Windows.old`，以及页面文件占了多少。
  页面文件只显示不可勾选：关掉它，内存吃紧时程序会直接崩，而不是变慢。
- **大文件** —— 在你指定的目录里、超过你指定体积的，从大到小。
- **目录占用** —— 哪些目录在占地方，一次看一层。
- **重复文件** —— 先按体积分组，再比每个文件头尾各 64 KB 的采样，最后才做全量比对。
  三关都过才算重复。每组自动替你留下路径最短的那一份，其余默认勾选——
  一百组不该变成一百个决定。
- **磁盘** —— 优化前先读介质类型。机械硬盘做碎片整理，固态硬盘做 TRIM。
  **就算你手动选，Tessera 也拒绝对固态硬盘做碎片整理**：毫无收益，纯粹磨损硬件。

### 启动与右键

登录时会跑的一切，来自四个地方——注册表、启动文件夹、计划任务、服务。只读注册表的工具会
报出寥寥几条，而机器开机依然要一分钟；计划任务那一半通常还更大。

**这里什么都不删。** 注册表项搬进备份键，启动快捷方式改名，计划任务通过计划程序禁用，
服务改成「手动」而不是「禁用」——禁用会让依赖它的东西一起启动失败。每一条都能一键还原。

同一个面板还列出挂在右键菜单上的每一个处理器（发布者从 DLL 的版本资源里读），以及弹窗拦截。
拦截分两层：禁用那些会弹广告的计划任务和自启项，再监视窗口、对命中规则的发 `WM_CLOSE`。
它**从不结束进程**，**从不碰你正在操作的那个窗口**，并且把关掉的每一个都记进日志——
误拦了要查得出来是哪条规则干的，并能一键加白名单。

### 软件管理

机器上装的全部软件，从三个注册表位置读全——64 位、32 位、以及只给当前用户装的。
只读第一处会漏掉一半以上，而一份缺了你明明装过的软件的列表，是一份你会立刻不再信任的列表。

占用大小是**实际数出来的**，不是安装器自报的那个数字（那个数字经常是 0 或者严重不准）。
卸载走软件自己的卸载程序；Tessera 绝不自己去删安装目录——那样会留下服务、驱动和注册表项。

注册表那一页明说了：清理失效引用**不会让电脑变快**。注册表是一棵树，跳过几条废项的开销
量不出来。做它是为了整洁。唯一真正有用的一类是指向已不存在 DLL 的组件注册——
Windows 每次构建菜单都会试着加载它们。

### 工具箱

四十二个小工具（带搜索和常用置顶），每个都配一句「什么时候用得上」而不是「它是什么」：刷新 DNS 缓存、查端口被谁占了、
查文件被谁锁着、重启资源管理器、重建图标缓存、找空文件夹、找长到复制和备份都会失败的路径、
带预览的批量改名，等等。

hosts 文件**只读显示**。改它能劫持互联网上任意一个站点，这不是一个加密保险库该替你握着的能力。


## 跨设备同步

手机、平板和这台电脑共用一个剪贴板和一个文件投递口。在手机上复制一个公式，在电脑的 Word 里
直接粘贴；在电脑上丢一个 4 GB 的视频，到平板上接着拿。全程不经过服务器：设备之间走你自己的
局域网直连，端到端加密。

### 配对一台设备

打开**跨设备 → 添加设备**，然后二选一：

- **出示我的配对码** —— 屏幕上出现一张二维码，用另一台设备扫。
- **输入对方的配对码** —— 把另一台设备上显示的码粘贴进来。
- **附近的设备** —— 列出这个网络里还没配过的设备，点一下就能配，全程不用传任何码。
  列表里的名字都标着*未验证*：设备名是对方自己填的，真正证明身份的是下面那步安全码核对。
- **手动输入地址** —— 前面几种都不行时的兜底，也是最可靠的一种。这一页上半部分显示本机
  地址（形如 `192.168.1.7:52140`）念给对方，下半部分填对方的。可以填 `IP:端口`，也可以
  只填 IP：只填 IP 时，Tessera 会向对方的发现信标询问当前实际端口。两台设备只要 IP 能通就配
  得上：不要求在同一个网段，组播被屏蔽也不影响。

**附近列表一直是空的时候，请点「扫描局域网」，不要反复点「刷新」。** 刷新只是把已经"听到"
的读一遍，而很多路由器会丢掉自动发现用的组播包——那种网络里刷一百次也还是空的。扫描是主动
挨个问一遍，绕开这个问题。

页面顶部出现黄色横条，说明 Windows 防火墙挡住了同步服务，别的设备看不到这台电脑。点
**一键放行**——弹一次权限确认，规则覆盖 Windows 的全部网络配置文件，但只限 Tessera 的
同步程序：它只回应发现探测和加密 QUIC 握手，没有配对就什么也读不到。Windows 丢掉被拦截
的数据包时是完全静默的：不报错、不记日志，界面上只剩一个空列表，所以这件事值得直接摆出来，
而不是让人自己猜。列表下面的**连接诊断**会逐项检查——监听、本机地址、局域网公布、应答端口、
自动发现、主动扫描——直接告诉你卡在哪一步、该怎么办。

接着两边会各显示同一组六位数字和六个表情。**请核对。** 一致就两边都确认；不一致说明中间有人，
选「不一致」，配对立即作废。配对码只能用一次，一分钟后过期，所以旧截图对任何人都没用。

配对时要选这台设备属于哪一类：

| | 长期 | 临时 |
|---|---|---|
| 适用于 | 自己的设备 | 别人的设备——同学的电脑、公共机器 |
| 自动重连 | 是 | 否 |
| 剪贴板同步 | 是 | 否 |
| 到期 | 永不，除非你撤销 | 10 分钟 / 30 分钟 / 1 小时 / 1 天 |
| 凭据是否落盘 | 加密保存 | 完全不写进磁盘 |

任何设备都可以随时撤销。撤销立即生效且不可挽回：旧凭据在下一次连接尝试时就失效，不用等重启。

### 复制与粘贴

你复制的内容会发给长期设备，并直接落进它们的系统剪贴板，随手就能粘。纯文本、富文本和图片会
按接收端应用真正能用的表示送达，公式和物理符号原样保留——`E = mc²`、`m/s²`、`θ̇`、`∑∫√`。
只同步最新一次复制，不会让旧内容晚到后覆盖你刚复制的新内容。Windows 每 200 毫秒检查一次；
Android 10 及以上受系统限制，只有 Tessera 在前台才能读取系统剪贴板，所以在别的安卓应用里复制后
回到 Tessera 一次即可同步。收到的内容仍会写进安卓系统剪贴板。

大图不会主动推送；只有你真的去粘贴时，对方设备才按需拉取。

### 发送文件

在设备列表里选中一个或多个目标，然后点**发送文件**。可以明确选一对一或一对多；文件、文件夹、
图片和应用安装包都会在传输列表里标明种类。每台设备各走各的传输：慢的手机不会拖住快的电脑，
某一台拒收或失败也不会连累其他几台。

每条进行中的传输都会显示名称、进度、速度和预计剩余时间；收发两端都能暂停、继续或取消。暂停会
保留已经验证收到的块；断开或重连后会从那里续传，不必从头开始。每个文件到达时都会校验，校验不过
就明确报失败，绝不显示成「已完成」。

收到的可执行文件（`.exe`、`.msi`、`.apk`）一律当普通文件保存。Tessera 从不运行或安装任何收到的东西。

### 保持连接

掉线的设备——手机锁屏、笔记本睡眠、切换 Wi-Fi、路由器重启——会自己连回来。没有「重连」按钮，
也不需要重新扫码。

重连是几条路同时发车（上次成功的地址、历史地址、以及局域网发现当前报出来的地址），谁先接上
用谁。在局域网里通常远小于一秒就完成。因为发现是实时的，所以哪怕对方换了 IP——换了 Wi-Fi、
重新拿了 DHCP、换了网段——照样能找到。

### 这个版本实际包含什么

Windows 这一侧是完整的，已经打进这次发布：同步服务就在 exe 里，随应用一起启动。

**安卓端用的是同一份协议核心**，经 `gomobile bind` 编译成原生库（`tesseracore.aar`），
所以配对、加密、重连状态机、断点续传跑的**就是 Windows 上那份代码**，不是另写一遍、迟早走散的
副本。安卓侧只加了真正跟平台有关的东西：保活的前台服务、让息屏后 mDNS 发现仍然有效的
Wi-Fi 组播锁、以及系统剪贴板的读写。

枚举网卡属于平台相关的那一类。安卓封掉了 Go 标准库用来做这件事的内核调用，所以安卓端改用
Java 的接口读取网卡清单，在节点启动之前交给共用核心，之后每次网络变化再交一次。没有这一步，
所有发现路径——附近的设备、扫描局域网、手动配对要念给对方的本机地址——都会是空的，而且不会有
任何东西告诉你为什么。**附近的设备**里那个连接诊断把网卡数放在第一条，也是这个道理：它是最该
先排除掉的一项。

界面由可折叠的分区拼成。此刻用不到的东西——配对码、应用更新、应用锁、故障日志——收起来只剩
一行标题，下次打开还是收着的。已配对设备列表和发送动作不折叠：这个页面就是为它们存在的。
还可以打开实时指标——在线设备数、链路延迟、当前传输速度、本次累计、监听端口、本机地址、
可用网卡——数都来自本来就在流动的事件，后台不会为它们多轮询一次，分区收起时那个定时器根本不跑。

安卓客户端已覆盖：扫码配对、安全码核对、设备列表、剪贴板收发、选择一个或多个目标发送文件、
传输控制、自选收到的文件存到哪里，也能多选撤销已配对设备。附近发现到已配对且在线的设备时，
会明确显示该状态，不会再让你无意义地重复配对。二维码识别用的是内置模型而不是需要下载的那种——
扫码配对最常发生在"手机刚装好、还没连上网"的时候，那正是下发式模型用不了的时刻。

安卓端还能检查自己的更新，比对的是本仓库的 release。**自动检查默认开着**：每次打开应用查一次，
只有确实存在新版才会提示你。关掉它就只在你按 **检查更新** 时才查。自动的只是**检查**这一步——
安卓不允许旁加载的应用静默安装另一个包，最后那次「安装」永远是系统自己弹的框、由你再确认一次。
下载只认 github.com，其余地址一律拒绝；新包能不能覆盖装上，由系统按签名密钥说了算。

它经过编译和签名，但**没有**在真机上跑过，第一次安装请当作试用。

### 安全

每台设备都有自己的长期密钥对，首次运行时生成，存进 Windows DPAPI ——绝不用硬盘序列号、IMEI
或 MAC 地址，因为那些东西撤销不了。在同一个网里不代表任何权限：每次连接都要重新对照你配对时
确认过的那把密钥验证身份；某台设备的密钥突然变了，会当场明确报警而不是悄悄放行。

每次连接都会重新协商一次性密钥，所以就算有人录下今天的流量、日后又偷到设备密钥，也解不开。
收到的文件路径在落盘之前先检查——`../` 逃逸、绝对路径、Windows 保留文件名一律拒绝。

### 怎么把设备连起来

电脑上打开**跨设备 → 设备与同步 → 生成配对码**，手机上点**扫码配对**对准二维码。
两边会各显示一组六位数字和六个表情——核对一致，两边都确认，就完成了。

两端都可以自己选收到的文件存到哪；改设备名不用重连，已配对的设备约十秒内就会看到新名字。

扫码之后一直没反应，最常见的原因是两台设备不在同一个网里，或者 Wi-Fi 开了 AP 隔离
（公司、学校、酒店的网络很常见）。用手机热点试一下最容易分辨是哪一种。
完整步骤和排查表：[连接指南](modules/file_vault/crossdevice/docs/06-连接指南.md)。

### 传输进度

传输一开始就会出现进度卡：文件名、目标设备、百分比、已传 / 总大小，一个文件一行。
每 250 毫秒刷新一次而不是每块刷——一块 4 MB，千兆网下一秒几十块，每块都刷界面反而
一顿一顿的。

### 故障日志

故障日志在导航栏里有自己的入口，设置里也有同一份——同一个开关、同一份内容，从哪边进都一样。
它**默认关闭**。打开后只记录出问题的地方——快捷键没生效、设备连不上、
服务起不来。它不记录你在做什么：不记剪贴板正文、文件名、路径、密钥。

它刻意是明文而非加密的：最需要日志的场景恰恰是「金库打不开」，而那时候加密的日志根本读不出来。
也正因为是明文，它必须默认关闭。一个按钮即可全部删除。

### 连接需要什么条件

两台设备必须在同一个局域网——同一个 Wi-Fi，或者电脑插网线接在同一个路由器下。
除此之外别无要求：不用账号、不经云端、不用端口转发。

监听端口不是固定的。默认端口被占用时会退到系统分配的端口；配对码和 mDNS 公布的
都是实际用的那个端口，所以后面的环节不关心它是几号。

电脑上开着 VPN 或代理没关系——公布地址时会跳过没有组播能力的接口（VPN 隧道正是
这种），所以手机不会拿到一个它根本到不了的隧道地址。

应用绕不过去的是 **AP 隔离**：很多公司、学校、酒店的网络禁止同一个 Wi-Fi 下的设备
互相通信。用手机热点试一次，既能确认是不是这个原因，也是最快的绕过办法。


## 安全模型

双层信封加密：

```
                  ┌─ 密码 ─────────────┐
                  ├─ 邮箱验证码 ───────┤
身份主密钥        ├─ 验证器动态码 ─────┤   五种方式各自独立包裹一次 IMK
  (IMK)      ─────┼─ Windows Hello ────┤
                  └─ 恢复密钥 ─────────┘
                           │
                           ▼
    每个文件一把全新的文件密钥 (FK)，用它分块加密文件内容；
    FK 再用 IMK 包一次，存进 .ivault 的头部
```

- 身份层（IMK 包裹、密钥槽位）**始终**是 AES-256-GCM，你选的算法只影响文件内容。
- 密码和恢复密钥的槽位用 **scrypt（N=2¹⁷、r=8，OWASP 当前的最低建议）** 派生包裹密钥：
  每猜一次要占约 134 MB 内存 —— 这才是让 GPU / ASIC 集群失效的关键，几千个并行核心
  在每核都要 134 MB 的前提下毫无意义。每个槽位都记着自己是用什么成本封的，所以以后
  再调高也不会把已有金库锁死；成本还停在旧值的槽位会在下次解锁时被静默重新封装。
- 所有盐值和密钥都是在**用户自己机器上**用 `os.urandom` 现场生成的 —— **exe 里不含
  任何秘密**，同一个安装包发给一千个人，得到的是一千个互不相干的金库。
- 剪贴板 / 笔记 / AI 历史的数据库是 SQLCipher，密钥由 IMK 经 HKDF 派生 —— 不用你另外
  记一个密码，但也意味着金库锁着的时候这些内容同样读不了。
- 渲染进程拿不到 Node 和文件系统权限（`contextIsolation: true`、
  `nodeIntegration: false`），只能通过一个很窄的 preload API 调后端。
- **任意一种方式即可解锁**，所以整体强度取决于最弱的那一环 —— 密码一旦泄露，其余四道
  防线形同虚设。要求多个因素同时满足的模式，当前版本不支持。

## 数据存在哪

| 内容 | 位置 |
|---|---|
| 身份、各个加密数据库、附件 | `%LOCALAPPDATA%\Tessera\data`（可更改，见下）|
| 验证器种子、邮箱密钥、SMTP 密码 | Windows 凭据管理器 |
| 解锁后的主密钥 | 只在后端进程内存里 —— 从不落盘 |

> **从叫「Ideal1 File Vault」的旧版本升上来？** 金库会自动搬家。首次启动时应用会去找旧的 `%LOCALAPPDATA%\Ideal1 File Vault\` 目录并迁移过来，走的是和其他搬家一样的事务式流程：SQLite 一致性快照、先校验后原子改名、**旧目录原样保留**，所以迁移失败也不会有任何损失。你当初在安装程序里选过的自定义位置也会一并继承。

不会上传到任何地方。所有出站连接都是你自己配的：发验证码用的你自己的 SMTP 服务器、
你选的 AI 接口（如果用助手）、测速目标，以及检查更新时的 GitHub Releases。

身份数据绑定单台电脑，换机器不会自动带过去。`data/` 已在 `.gitignore` 里，不会被提交。


### 金库存在哪，可以自己选

默认位置对多数人够用。想放到别处——你真正会备份的那块盘、加密卷、第二块硬盘——有三
种方式，按优先级：

1. **`IDEAL1_FILE_VAULT_DATA_DIR`** 环境变量。优先级最高，只对这一次运行生效，并且
   会关闭所有自动搬迁——设了它就说明这个目录由你自己管，应用不插手。
2. **安装程序。** `Tessera.Setup.exe` 在选完程序安装位置之后，单独有一页
   问数据目录。这是两个不同的决定：装错了重装一遍就好，而一个用了半年的金库放错
   地方，代价完全不同。
3. **设置 → 关于 → 更改位置。** 选好新目录然后重启。搬迁发生在下次启动时、任何东西
   打开金库**之前**——在连接开着的时候复制加密 SQLite 数据库，会悄悄丢掉还留在 WAL
   里没落盘的那部分。旧目录原样保留，搬失败不会有任何损失。

卸载应用永远不会删除数据目录。

## 开发

```
core/       跨模块公共基础设施：配置、日志、模块发现、外部命令
modules/    可插拔功能模块，一个子文件夹 = 一个独立场景
scripts/    CLI 入口：run.py（list / run <module>）

tests/      冒烟测试
```

开发约定，完整版见 [`CLAUDE.md`](CLAUDE.md) 和 [`modules/README.md`](modules/README.md)：

- Python ≥ 3.9。中文输出用 `python -X utf8 …`。
- 模块之间**不互相 import**，只依赖 `core/`；共用逻辑提升到 `core/`。
- 模块内部可混用 JavaScript / C，统一通过 `core/proc.py` 的 `run_command()` 调用。

新增一个场景：复制 `modules/_template/` → `modules/<name>/`，改 `MODULE_META`，
实现逻辑，`python scripts/run.py list` 确认被发现。

```bash
python -m pytest tests/                        # 冒烟测试
python -m pytest modules/file_vault/tests/     # 金库测试套件
cd modules/file_vault/ui && npm run lint       # 前端 lint
```

## 构建发布版

构建**必须在 Windows x64 上跑** —— PyInstaller 不是交叉编译器。

```powershell
cd modules\file_vault\ui
npm install
npm run build:standalone
```

它会依次编译原生 C 助手、用 PyInstaller 冻结两个 Python 目标，然后跑
`tsc` + `vite build` + `electron-builder`，产物在
`ui/release/<版本>/` 下的两个产物：`Tessera.exe`（免安装版）和
`Tessera.Setup.exe`（安装版）。

签名由构建自己完成：首次构建时创建证书、把公钥钉进 `signer-policy.json`、把私钥以**不可导出**的形式留在证书存储里，并在仓库之外写一份带密码保护的备份。这里没有需要手工做的事。（仓库根目录的 `secure-signing-key.cmd` 可以用你自己的口令重新保护那份备份——只有在你希望备份能挺过这台机器报废时才需要。）

推一个 `v*` tag 会在 CI 里跑同样的构建，见
[`.github/workflows/build-windows.yml`](.github/workflows/build-windows.yml)。工作流把一份
**未签名**的 exe 传到 draft release 就停下。代码签名**刻意**只在你自己的机器上做：
签名私钥一旦进了 CI secrets，任何能改 workflow 的人都能拿它签任意东西，签名就退化
成纯粹的形式。

你自己 fork 后发布前必须填两个占位符：

- `modules/file_vault/ui/electron/updateService.ts` 里的 `REPO` → 你的 `owner/repo`

只有这一处要手工改。签名证书在你第一次跑 `npm run build:standalone` 时**自动创建**，
公钥指纹自动写进 `signer-policy.json` 等你提交。之后每次构建都会重新核对「即将用来
签名的证书」是不是钉的那一张，不是就停——否则换台机器重新构建会静默产出一个所有
已安装客户端都拒绝的版本，而且在用户点更新之前看不出任何异常。

**证书不用花钱。**「把签名内嵌进 exe」和「向 CA 买证书」是两件独立的事：Authenticode
的格式不关心证书是谁签发的，而在客户端里钉死公钥其实**比信任 CA 更强**——攻击者要
冒充你得直接拿到你的私钥，而不是从几百家公信 CA 里骗一张同名证书。花钱买到的是
SmartScreen 信誉，也就是首次运行时不弹「Windows 已保护你的电脑」。

`SIGNER_POLICY` 留空应用照常能用 —— 只是拒绝自我更新，并明确说明原因。

完整流程（含证书到期怎么办、以及为什么一个 release 恰好是两个文件）：
[`docs/standalone-exe-release.md`](docs/standalone-exe-release.md)
